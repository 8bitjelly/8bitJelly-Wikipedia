# Coding Standards in 8BitJelly

Welcome to the **Coding Standards** section of our documentation.  
Here, you’ll find the agreed-upon rules and practices that help us keep our codebase **consistent, maintainable, and scalable** across all projects.

These standards are meant to guide both new and experienced team members, ensuring we all write code that is easy to read, test, and extend - no matter the size of the game.

---

## Sections

### Architecture Guidelines
How we structure our code, organize responsibilities, and ensure that projects remain flexible and easy to expand.

---

### Best Practices
A collection of what to **do** and what to **avoid** while writing code. Covers common pitfalls, style preferences, and good coding habits.

---

### Formatting & Style
How we write and format our code to ensure consistency:
- Bracket placement.
- Code indentation.
- Method separation & decomposition.
- Commenting standards.

---

### Git Workflow
Our Git rules and conventions:
- Branch naming standards.
- How we write commit messages.
- Code review requirements.

---

### Variables
Guidelines for naming variables, methods, and classes consistently, including casing rules and when to use prefixes.

---

## Purpose
The goal of these standards is not to limit creativity but to:
- Ensure that **everyone’s code looks and feels the same**.
- Reduce time wasted on misunderstandings or refactoring.
- Make collaboration smooth across different roles (developers, designers, artists).
